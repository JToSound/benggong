## 1. 向量底圖（解決「放大起格」）

### 1.1 為何 raster LOD 冇得救

舊做法係 raster LOD 圖磚：**輸出尺寸固定、改細 bbox 就等於放大**。
根本限制係「**冇圖磚覆蓋嘅地方冇得放大**」——

```
最細圖磚：tko-campus-core  span 0.020°（將軍澳）
最大縮放：0.70° / 35 = 0.020°
→ 將軍澳：1:1，鋭利
→ 屯門／元朗／沙田：只能用 hk-nw（span 0.355°）
→ 拉伸 0.355 / 0.020 = 17.75 倍 → 必然起格
```

要覆蓋全港街道級（1.3 m/px），raster 需要約 **670 MB** 圖磚 —— 唔可行。

### 1.2 做法：由本機 OSM 產生向量圖磚

資料源係專案已有嘅 `data/private/cache/osm-hk.json`（182 MB、198,300 個
元素），**完全離線**，唔會再連 Overpass。

新增 `scripts/build_vector_basemap.py`：

| 圖層 | 內容 | 大小 |
|---|---|---|
| `land.json` | 83 個陸地環（由海岸線推導） | 90 KiB |
| `water.json` | 1,761 個內陸水體 | 126 KiB |
| `areas.json` | 1,632 個公園／工業區 | 120 KiB |
| `roads-l0.json` | 10,953 條主幹道（class 0–2） | 322 KiB |
| `roads-l1.json` | 42,738 條道路（class 0–5） | 1,310 KiB |
| `labels.json` | 7,847 個地名標籤 | 500 KiB |
| `tiles/*.json` | 84 個圖磚（道路＋建築＋POI） | 8.9 MiB |

**首次載入 gzip 後約 320 KiB**；其餘按需載入。

### 1.3 過程中踩到嘅三個陷阱

**(a) 海岸線有真實資料缺口 —— 876 個連通分量**

初版以為「按 way 端點接龍」就得，結果得出「1599 個 degree-2 節點、
8 個 degree-1」→ 錯誤結論「只差 4 條鏈」。

真相要用**節點鄰接圖**（唔係 way 端點圖）才睇到：1,603 條海岸線斷成
**876 個連通分量**，大嶼山西岸有 3,504 m 缺口。唔補線嘅話，海水會由
缺口灌入島內，**大嶼山陸地只剩 3.1%**。

修法沿用 raster 版 `render_binggang_map.coastline_bridges` 嘅結論：
自由端按距離貪心配對補線（≤ 6 km）。呢個係 raster／vector 兩版**必須
共用**嘅拓樸修復。

**(b) 大陸主體冇閉環**

補完線之後仲有一條開放鏈 —— 大陸海岸線由后海灣（113.86, 22.56）
繞到沙頭角（114.24, 22.56），兩端相距 39 km，冇可能就近配對。
唔處理嘅話，**新界＋九龍＋將軍澳全部變成海**（實測 20 個測試點有
10 個錯）。修法：同一連通分量嘅兩個自由端直接連線。

**(c) 前端投影漏咗 `lat_min` 項**

`view.y` **唔係緯度**，而係「user unit y」：

```
userY(lat) = lat_min + (lat_max − lat) / cos(φ₀)
```

初版寫成 `(lat_max − lat)/cos − view.y`，漏咗 `lat_min` → 全部幾何偏離
約 22 個 user unit（即整個畫面以外）。**症狀係「海畫得出、陸地完全唔見」**。

### 1.4 驗證

`tests/vector-basemap.test.ts`（7 項）＋ `scripts/build_vector_basemap.py`
內置陸地幾何驗證（20 個已知地點：維港／將軍澳／中環／深圳／大嶼山／
屯門／沙田／青衣／長洲／機場／上水／元朗／大埔…全部正確）。

陸地幾何用 point-in-polygon 驗證：

```
OK  維多利亞港 sea    OK  將軍澳 land   OK  中環 land
OK  深圳 land        OK  南海 sea     OK  西貢 land
OK  大嶼山 land       OK  屯門 land    OK  沙田 land
OK  青衣 land        OK  長洲 land    OK  吐露港 sea
OK  機場 land        OK  上水 land    OK  元朗 land
OK  大埔 land        OK  藍塘海峽 sea
```

### 1.5 前端：Canvas 2D 渲染器

新增 `src/map/VectorBasemap.ts`。

**為何用 `<canvas>` 而唔用 `<svg>`**：一平方公里市區有幾千幢建築。
SVG 要為每個多邊形建一個 DOM 節點，5,000 個節點會令平移掉幀。
Canvas 冇 DOM 開銷，而且可以用 `setTransform` **一次過變換整批路徑** ——
平移／縮放唔需要重建路徑。呢個係 60 fps 嘅關鍵。

分層策略（按視窗經度跨度）：

| 跨度 | 層 | 內容 |
|---|---|---|
| > 0.35° | 0 | 陸地／水體／面層／主幹道 |
| 0.05–0.35° | 1 | ＋全部道路（class 0–5） |
| ≤ 0.05° | 2 | ＋街道級道路、**建築**、POI 標籤 |

⚠️ 道路分級表 `ROAD_MIN_LEVEL` **刻意喺 Python 同 TS 各寫一次** ——
兩邊唔一致會出現「有資料但唔畫」或者「畫咗但冇資料」，
兩者都冇錯誤訊息。`tests/vector-basemap.test.ts` 比對兩邊。

### 1.6 Raster 後備

Raster LOD 保留做**後備**（`fallbackToRaster()`），只有向量底圖真係
載入唔到（例如部署漏咗 `assets/vector/`）才啟用。
預設唔設 `href` —— 冇必要為咗一個平時唔用嘅 2 MB PNG 付流量。

## 2. 區域檔案（倖存區／病窩／據點）

### 2.1 由 18 個圓形 → 48 個檔案

舊做法 `derive_zones.py` 只由**地點名**推導區域，每個區域一句
≤120 字描述。用戶要「政權種類、人文風格、社會結構等等政治、民生、
架構等等嘅詳細內容」—— 呢啲要由**全文**抽取。

**做法**：8 個子代理各自讀 25 章（198 章全覆蓋），每個區域寫一份
dossier，再由 `scripts/merge_zone_dossiers.py` **確定性合併**。

結果：**93 條代理記錄 → 48 個區域**（11 倖存區、21 病窩、16 據點）。

### 2.2 合併規則（全部寫死喺腳本，可重跑）

| 規則 | 說明 |
|---|---|
| 同名合併 | 取各欄位**最完整**嘅值（最長字串）、章節聯集 |
| `kind` 衝突 | **多數票**（例如「靈實醫院」4 個代理話 nest、1 個 outpost、1 個 survivor → nest），票數分佈寫入 `kind_votes` |
| 子區域吸收 | 母區域名之後緊接**子部件詞**（地下層／上層／內…）才併入 |
| 通用詞過濾 | 「廣場」「商場」等唔可能係區域 |

⚠️ **踩過嘅陷阱**：初版只靠「前綴相同」就吸收子區域，結果
「將軍澳中心」（商場）被「將軍澳」（地區）吸走 —— 變成
「整個將軍澳都係病窩」。修法：要求前綴之後緊接子部件詞。

### 2.3 範圍推導

由成員地點推導，全部可稽核：

- 成員 ≥ 3 個 → **凸包 + 200 m 外擴**（證據）
- 否則 → 48 邊形近似圓（估算，地圖上畫虛線）

**三層防護**（實測每一層都觸發過）：

1. **離群點過濾** —— 離質心超過 2.5 × 中位距離就唔計
2. **核心點錨定** —— 以精確配對點定中心，只保留上限內嘅點
3. **硬封頂** —— 按類型封頂（倖存區 900 m／病窩 800 m／據點 550 m）

⚠️ 為何要封頂：實測「佛教志蓮小學」（**一間小學**）因為前綴配對拉到
11 個散落全將軍澳嘅地點，算出 **2,271 m** 半徑 —— 比整個坑口區仲大。

### 2.4 前端：範圍多邊形 + 圖騰 + 互動

- **多邊形**（唔再係圓）：`geometry.type = "Polygon"`
- **特別記認**：每類一個 SVG 圖騰 —— 倖存區 = 盾、病窩 = 警告三角、
  據點 = 旗。**為何要圖騰而唔止顏色**：顏色係最弱嘅編碼（色弱用戶
  分唔到紅綠），加圖騰之後形狀都可以分辨。
- **動效**：病窩有掃描光環（由中心向外擴散）。**只有病窩脈動** ——
  三種都跳就冇重點。
- **互動**：點擊 → 開區域檔案面板

### 2.5 區域檔案面板（`src/components/ZoneDossier.ts`）

分節顯示：政權／領袖與要員／社會結構／經濟／防禦／人口／人文風俗／
地標與設施／威脅／資料來源／出現章節。

**為何唔用 tab**：tab 會令用戶唔知道「仲有幾多內容未睇」。
分節卡片全部展開（證據除外）可以一眼睇到全貌，亦可以用 Ctrl+F 搜尋。

每個區域附**稽核欄位**：範圍證據、範圍可信度、座標證據、抽取來源、
原文引用 —— 令「點解係呢個範圍」可回溯。

## 3. 座標審核（解決「標錯座標」）

### 3.1 量化

```
704 個地點：exact 54、district 62、approximate 416、fictional 172
→ 588 個（84%）座標係「同章質心 + id hash 環形偏移」產生，即任意值
```

### 3.2 做法：`scripts/audit_location_coords.py`

三條確定性規則：

| 規則 | 內容 | 結果 |
|---|---|---|
| 1 地名重配 | 用 gazetteer（OSM 衍生）＋策展地名配對，距離 > 1,200 m 就修正 | 3 個 |
| 1b 子地點錨定 | 子地點（「靈實醫院第二層」）同母體距離 > 900 m → 錨定返母體附近 | 29 個 |
| 2 區外偵測 | 座標落喺故事舞台以外 | 0 個 |
| 3 同章離群 | 同章質心距離 > 6 km | 0 個 |

配套新增 `scripts/build_osm_gazetteer.py`：由本機 OSM 建立
**24,298 個名**嘅「地名 → 座標」索引（私有，唔 commit）。

### 3.3 兩個關鍵設計決定

**(a) 錨點一定要靜態**

初版用 `zones.geojson` 做錨點 → **循環依賴**：改地點 → 區域中心移動 →
再改地點。`test_pipeline_is_idempotent` 即時捉到。
改用 gazetteer（靜態）之後，錨定係純函數，冪等。

**(b) 唔可以覆蓋有推斷證據嘅座標**

`inferred_from` 係經審閱嘅推斷結果，而且
`test_applied_coordinates_match_inference` 會驗證「套用嘅座標 = 推斷記錄」。
審核跳過呢批地點。

### 3.4 一個「唔應該修」嘅個案

「海洋公園」（ch198）原本落喺將軍澳 —— 審核配對到**真實海洋公園**
（港島，距離 12,422 m）。查原文：ch198 寫明「海洋公園位於港島區」，
所以**修正係正確嘅**。

呢個個案揭示原有測試 `test_anchored_locations_stay_in_story_region`
嘅假設已經過時（「全部地點都喺將軍澳」）。已更新為：
**冇地名證據嘅地點**一律要喺區內；有證據（`coord_corrected`）嘅例外。

## 4. 未來感 HUD（解決「UI 簡陋」）

### 4.1 設計語言：「戰術 HUD」

新增 `src/styles/hud.css`（獨立檔案，載入次序喺 `main.css` 之後）。

1. **切角框** —— 用 `clip-path` 切走四角，取代圓角。
   圓角係消費級產品語言；切角係儀器／軍工語言。
2. **單色主調 + 單一強調色** —— 底調近黑藍，強調色只有青色
   （`#38e8ff`）。琥珀同紅只留畀「危險」語意，唔做裝飾。
3. **髮絲線** —— 1px 半透明線做分隔，唔用粗邊框。
4. **動效有方向** —— 進場由上而下、由左至右；唔用彈跳。
5. **掃描線 + 微網格 + 暗角** —— 令平面面板有「儀器」質感。

動效清單：頂欄游走發光線、圖例面板左滑進場、章節 chip 上浮、
區域徽記縮放、病窩掃描光環、檔案分節 stagger 進場、掃描線質感。

全部尊重 `prefers-reduced-motion`。

### 4.2 為何另開 `hud.css` 而唔係加落 `main.css`

`main.css` 已經 1,000+ 行、而且歷史上有過**重複嘅 `#topbar` 區塊**。
新設計全部收喺新檔案，邊界清楚，日後刪舊嘢唔會誤刪新嘢。

### 4.3 踩到嘅陷阱：HUD 硬寫死深色，令淺色主題爆掉

HUD 樣式預設寫死深色背景。淺色主題之下變成
**「深色底 + 深色字」**——按鈕文字完全睇唔到。

修法兩部分：
1. `hud.css` 加 `[data-theme="light"]` 覆蓋段
2. **Canvas 底圖亦要跟主題** —— canvas 唔會讀 CSS 變數。
   `theme.ts` 換 `data-theme` 之後派發 `basemap-theme-change` 事件，
   `VectorBasemap` 訂閱並換配色（`PALETTE_DARK` / `PALETTE_LIGHT`）。

⚠️ 為何用事件而唔係直接呼叫：`theme.ts` 唔應該知道地圖嘅存在
（依賴方向係 app → theme）。事件令主題模組保持零依賴。

## 4.4 收尾階段修好嘅三個回歸（全部由 e2e 測試捉到）

### (a) 匯出 PNG 冇底圖 —— 真 regression

`exportMap.ts` 係將 SVG 序列化再畫落 canvas。向量底圖**唔喺 SVG 樹入面**
（係獨立嘅 `<canvas>`），所以匯出結果得一層標記 ——
實測 PNG 由 800 KB 跌到 **58 KB**。

修法：`exportMapPng()` 新增 `underlay` 參數，先畫底圖再畫 SVG。

### (b) 圖磚快取策略令測試逾時 —— 效能 regression

初版喺每次 `ensureTiles()` 都刪走唔喺目前視野嘅圖磚。睇落合理
（省記憶體），但代價係**每次平移／切章都要重新 `JSON.parse`
最多 1 MiB 嘅圖磚**。

實測：`phase-i.e2e.test.ts` 嘅「逐章掃 198 章」測試由 30 秒變成
**超過 120 秒逾時**。瀏覽器 HTTP 快取幫唔到手 —— 瓶頸係**解析**。

修法：改為 LRU（留 24 個圖磚）。同一測試變回 **48.7 秒**。

順帶修好一個純浪費：原本每次載入圖磚都 `JSON.stringify(d)` 嚟量度大小，
而圖磚可以係 1 MiB。改用「記錄數 × 40 bytes」估算。

### (c) 道路發光蓋過地形

初版對**所有**道路都描發光邊。街道層有 2,000+ 條路，重疊起上嚟變成
一層均勻嘅琥珀色霧，蓋過建築同綠地。

修法：發光只畀 class ≤ 2（高速／幹道／主要道路），並隨縮放層遞減
（0.35 / 0.55 / 0.75）。

### (d) 測試基礎設施：e2e 檔案唔可以並行

3 個 e2e 檔案各自開一個 Chromium，仲要共用一個 preview server。
並行嘅話 CPU 爭奪會令個別測試由 25 秒變成超過 120 秒逾時 ——
實測 `visual-smoke.e2e.test.ts` 單獨跑 14 項全過，同其他檔案一齊跑
就有 2 項逾時。呢類「假失敗」比慢更難處理。

修法：`vite.config.ts` 設 `fileParallelism: false`。

### (e) 舊 e2e 斷言已經過時

- `phase-i.e2e.test.ts`：「`#basemap-group` 嘅 href 應該係 hk-basemap PNG」
  → 改為驗證向量 canvas（存在、有尺寸、ready、縮放後像素內容改變、
  層級屬性更新）
- `phase-j-lod.test.ts`：「圖磚由 hk-basemap 變成 tko-*」
  → 改用 `data-basemap-level`（0 → 1 → 2）

⚠️ 「縮放之後 canvas 像素內容必須改變」呢個斷言好重要 ——
佢係「有渲染但冇重繪」嘅**唯一**可靠檢查，一般「元素存在」嘅斷言捉唔到。

## 5. 改動檔案清單

### 新增

| 檔案 | 用途 |

## 7. 已知限制

1. **建築只喺街道級（≤0.05°）出現**。中間層（0.05–0.35°）冇建築 ——
   實測該層每像素約 4–30 m，建築多數係亞像素，畫咗反而變雜訊。
2. **圖磚總量 8.9 MiB**，市區單一圖磚最大約 1 MiB（gzip 後約 213 KiB）。
   已按需載入，但首次放大到市區仍需約 0.8 MiB。
3. **區域範圍係「示意」而唔係測繪**。凸包由成員地點推導，唔代表
   故事世界嘅實際邊界。
4. **gazetteer 只覆蓋故事舞台**（將軍澳／西貢／九龍東），
   因為索引太闊會令「商場」呢類通用名撞到全港幾十個結果。
5. **`fictional` 精度地點仍然係估算座標**（172 個）。佢哋冇對應真實
   地物，只能靠所屬區域錨定 —— 呢個係資料本質限制，唔係 bug。

## 8. 下一步（全部程式化）

1. **擴充自動驗證規則**：加「區域幾何唔可以互相包含超過 80%」
   （捉重疊區域）、「圖磚內 POI 標籤唔可以超過 2,000 個」。
2. **加多啲語義約束**：為 `government` / `economy` 等欄位加
   最小長度同關鍵詞檢查，捉空泛輸出。
3. **向量圖磚壓縮**：目前用 JSON delta 編碼。可考慮 varint + base64，
   預計再減 40%。
4. **中縮放層建築**：可加一層 0.15° 格、重度簡化嘅建築圖磚，
   覆蓋 0.05–0.35° 呢個空窗。
5. **區域關係圖**：區域之間有「納貢」「敵對」「同盟」關係
   （例如大本營淪為不良人附屬領土），可以做成力導向圖。
